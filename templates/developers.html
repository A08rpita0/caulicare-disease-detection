{{ icon('info') }} API

Use CauliCare as an inference service

Send a leaf photo, get the predicted class, a confidence score and a machine-readable decision. Every request is validated, timed and logged with a request id. The full contract is in the OpenAPI specification.

{{ icon('gauge') }} Classify one image

Small response, fastest path (no Grad-CAM, no similarity search):

curl -X POST "{{ base_url }}/api/predict?compact=1" \
  -H "X-Request-ID: my-trace-0001" \
  -F "image=@leaf.jpg"
{
  "success": true,
  "decision": "accepted",
  "decision_reason": "The top class has 98.7% probability (high confidence).",
  "result": {
    "label": "Black Rot",
    "confidence": 0.9871,
    "confidence_percent": 98.7,
    "confidence_level": "high",
    "reliable": true,
    "top_k": [{"label": "Black Rot", "confidence": 0.9871, "percent": 98.7}, ...]
  },
  "inference": {"backend": "onnxruntime", "model": "model1.h5"},
  "timing_ms": {"quality_gate": 38.5, "leaf_check": 412.0,
                "preprocess": 9.8, "inference": 3.1, "total": 489.6},
  "cached": false,
  "request_id": "my-trace-0001"
}

Without compact=1 the response also contains all class probabilities, Grad-CAM images, the affected-area estimate, similar reference images and disease information.

{{ icon('compare') }} Classify up to {{ batch_max }} images at once

curl -X POST "{{ base_url }}/api/predict/batch" \
  -F "images=@leaf1.jpg" -F "images=@leaf2.jpg" -F "images=@notes.pdf"

Each image is checked on its own; a bad file is reported in its entry and does not stop the others. The accepted images share one batched forward pass through the model. A batch of N images counts as N requests against the rate limit.

{
  "count": 3, "accepted": 2, "uncertain": 0, "rejected": 1,
  "results": [
    {"index": 0, "success": true, "decision": "accepted", "result": {...}},
    {"index": 1, "success": true, "decision": "accepted", "result": {...}},
    {"index": 2, "success": false, "decision": "rejected",
     "code": "unsupported_extension", "http_status": 415}
  ]
}

The decision field

ValueMeaning
acceptedTop class probability is at least {{ '%.2f'|format(low) }}. Moderate (below {{ '%.2f'|format(high) }}) or high confidence.
uncertainA prediction is returned, but its probability is below {{ '%.2f'|format(low) }}. Do not act on it automatically.
rejectedRefused before classification: unsupported or corrupted file, too large, poor quality, or not a cauliflower leaf.
errorA valid request the service could not complete (model unavailable, rate limit, internal error).

Scores are over-confident (mean top score 96.8% against 87.9% test accuracy), so even accepted results can be wrong.

What makes it fast and reliable

  • ONNX Runtime. The CNN is also exported to ONNX, and Grad-CAM is computed from its activations. The ONNX model is compared with the Keras model when the server starts and is not used if they differ. It can also run without TensorFlow at all (INFERENCE_BACKEND=onnx), which needs a fraction of the memory.
  • Result cache. An identical upload (same bytes) is answered from memory. Only a hash and the finished result are kept, never the image.
  • No wasted work. compact=1 and the batch endpoint skip Grad-CAM, the affected-area estimate and the similarity search, and decode each image once.
  • Per-stage timings in every response (timing_ms), and one structured log line per request with the request id, status, latency and decision, never the file name or image.
  • Fail closed. If the cauliflower-leaf check cannot be made, the upload is refused with 503 rather than analysed unverified.
